# 64비트 환경과 ARM

디컴프 런타임은 32비트 x86 프로그램으로 작성되어 있습니다. 포트는 이것을 64비트 환경과 ARM용으로도
빌드합니다. 휴대폰이 바로 그런 환경이기 때문입니다. 이 문서는 그렇게 해도 되는 이유, 검증 방법,
빠진 부분을 설명합니다.

## 왜 되는가

런타임은 DS 메모리를 DS의 원래 주소(메인 RAM `0x02000000`, ITCM `0x01ff8000`, DTCM `0x027e0000`)에
매핑하고, 인터프리터는 DS 주소를 그대로 포인터로 씁니다. 그래서 `runtime/memory.c`는 포인터가
32비트가 아니면 빌드를 거부합니다.

하지만 인터프리터에 실제로 필요한 것은 그 주소들을 그대로 매핑할 수 있다는 것뿐이고, 그 주소들은
모두 4GiB 아래에 있습니다. 64비트 프로세스도 32비트 프로세스와 똑같이 매핑할 수 있습니다. 64비트
프로세스가 못 하는 것은 그 반대, 즉 *호스트* 포인터를 DS 워드에 담는 일입니다. 그것은 Native와
Clean 형태(일치 소스를 호스트용으로 컴파일한 것으로, 구조체가 DS의 것 그대로임)만 필요로 합니다.
포트는 모든 함수를 ROM의 코드 그대로 인터프리터에서 돌리는 **Reference 형태**로 실행하며, 이 형태는
64비트로 경고 하나 없이 컴파일됩니다.

그래서 64비트 환경에서 포트는 디컴프를 고치는 대신 `memory.c`의 검사에 답해 주고
(`port/compat/memory_64bit.h`, 그 파일 하나에만 강제로 포함), 디컴프의 x86 전용 호스트 코드는
Reference 형태에 필요한 두 가지(DS 주소 범위 예약, 크래시 보고)만 남긴 대체 코드로 바꿉니다
(`port/src/native_os_portable.c`).

## 어떻게 검증하는가

디컴프에는 입력 녹화와, 각 녹화가 만들어 내야 하는 프레임의 SHA-1이 들어 있고
(`decomp/runtime/recordings/`), 디컴프는 32비트 x86 PC에서 이것으로 스스로를 검사합니다.
`port/tests/test_frames.py`는 같은 녹화를 포트 빌드에서 재생해 비교합니다.

```sh
python3 port/tests/test_frames.py 한국판.nds build                # 이 PC
python3 port/tests/test_frames.py 한국판.nds build-aarch64 --run "qemu-aarch64 -L /usr/aarch64-linux-gnu"
```

| 환경 | `title-start` (1,300프레임) | `new-game` (13,760프레임) |
|---|---|---|
| x86 32비트 (디컴프의 호스트 코드와 블록 번역기 그대로) | 프레임 일치 | 프레임 일치 |
| x86-64 | 프레임 일치 | 프레임 일치 |
| ARM 64비트 (`aarch64`, qemu-user) | 프레임 일치 | 프레임 일치 |
| ARM 32비트 (`armhf`, qemu-user) | 프레임 일치 | 프레임 일치 |

"프레임 일치"는 모든 프레임의 두 화면이 비트 단위로 같다는 뜻입니다. ARM 빌드는 크로스 컴파일러로
만든 Linux 프로그램이고(`port/cmake/linux-aarch64.cmake`, `linux-armhf.cmake`,
`-DPORT_FRONT_END=OFF`), Android 라이브러리는 같은 소스를 NDK로 빌드한 것입니다.

## 휴대폰에서 다른 점

- **그 주소 범위가 앱 프로세스에서 비어 있어야 합니다.** Android 앱은 Java 런타임의 메모리가 이미
  매핑된 채로 시작합니다. 지금까지 시험한 유일한 시스템인 Android 14 에뮬레이터(x86-64 이미지, 앱은
  64비트 프로세스)에서는 DS 주소가 비어 있었고 게임이 부팅되어 실행됐습니다. 모든 휴대폰에서 그렇다는
  보장은 없습니다. 실행이 `cannot map the DS memory`로 멈추면 이 문제이며, 메시지와 앱 파일의
  `log.txt`에 그렇게 나옵니다.
- **속도.** ARM용 블록 번역기가 없어서(디컴프의 것은 x86 코드) 모든 명령을 해석합니다.

## 빠진 것

Native와 Clean 형태. 32비트 포인터가 필요하고, 지금 코드로는 x86도 필요합니다(docs/roadmap.ko.md).
