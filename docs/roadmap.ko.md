# 로드맵

포트가 지금 무엇을 하는지와 나머지를 어떤 순서로 할지를 정리합니다. 디컴프에 관한 내용은 고정해 둔
커밋의 `decomp/`(`docs/runtime.md`, `docs/play.md`, 런타임 소스)를 기준으로 합니다.

## 현재 상태 (0.5.0)

| | 상태 |
|---|---|
| 포트에서의 게임 | 실행됨. 디컴프의 녹화를 재생하면 x86과 ARM, 32비트와 64비트 모두에서 디컴프와 비트 단위로 같은 프레임이 나옴([64bit.ko.md](64bit.ko.md)) |
| Android APK | `armeabi-v7a`와 `arm64-v8a`, CI에서 빌드. **실제 휴대폰에서는 아직 실행해 보지 않음** |
| Linux | x86-64와 32비트 x86, CI에서 빌드 |
| ROM 확인과 분리 | 디컴프의 `tools/extract.py`와 바이트 단위로 같은 모듈(`port/tests/test_rom_prep.py`) |
| 속도 | 인터프리터만으로 서버 CPU에서 DS의 2~3배. 휴대폰에서는 측정 필요 |
| 소리 | 켜짐: 런타임의 믹서를 SDL 오디오 장치로 출력. 실제 휴대폰에서는 아직 들어 보지 않음 |

## 디컴프 런타임의 전제

1. **DS 주소가 곧 호스트 포인터.** DS 메모리를 원래 주소에 매핑하고, `runtime/memory.c`는 32비트로만
   빌드됩니다. 그래도 Reference 형태는 64비트 프로세스에서 동작하며, 포트는 그렇게 빌드하고 프레임을
   검증합니다([64bit.ko.md](64bit.ko.md)).
2. **컴파일된 형태는 x86 전용.** Native와 Clean 형태는 x86 호출 규약으로 컴파일된 함수를 부르고
   (`runtime/host.c`), x86 예외 프레임으로 DS 코드 호출을 잡아내고(`runtime/native_os.c`), 코드에 x86
   점프를 덧쓰고, x86 어셈블리로 인터프리터에 들어갑니다(`runtime/native_tramp.S`). 포트는 Reference
   형태로 실행하고 이 파일들을 대체 코드로 바꿉니다.
3. **인터프리터 가속도 x86 코드**(`runtime/arm_x86.c`, 32비트 x86 전용). ARM에서는 모든 명령을 해석합니다.
4. **창과 소리는 Win32.** `runtime/play.c`와 `runtime/sound.c`의 출력 장치 부분(`waveOut`). 믹서 자체는
   이식 가능합니다.
5. **DS 크기의 소프트웨어 렌더러.** 두 화면을 런타임이 256×192로 그립니다(`runtime/gpu2d.c`,
   `runtime/gpu3d.c`).
6. **무선은 자기 콘솔끼리만.** 런타임은 한 PC에서 콘솔 두 대를 나란히 돌리는 실행을 위해 DS의 무선
   관리자를 시뮬레이션하고(프레임마다 파이프로 교환), 프로세스 안에서 시뮬레이션한 서버를 상대로 Wi-Fi
   커넥션도 다룹니다(`docs/multi-console.md`). 어느 것도 실제 네트워크로 나가지 않으며, 창(`play.c`)은
   콘솔 한 대만 실행합니다.

## 계획 (순서대로)

1. **64비트 휴대폰.** 0.2.0에서 휴대폰 없이 확인할 수 있는 데까지 완료. 다음은 실제 휴대폰에서
   실행해 보고, 속도를 재고, 깨지는 곳을 고치는 것입니다.
2. **휴대폰다운 조작.**
   - 세로 화면 우선: 완료. 그림이 창의 폭을 꽉 채우고, 버튼은 그 아래 남는 공간에 놓이며, 공간이 없으면
     (태블릿, 폴더블) 그림 아래쪽 위에 겹쳐집니다.
   - 풀터치 모드(버튼 없이 터치펜 조작만으로 플레이): 완료. 점 세 개 표시나 Android의 뒤로 버튼으로
     버튼을 켜고 끄며, 선택은 저장됩니다.
   - 버튼을 원하는 곳에: 완료. 버튼마다 끌어 옮기고 크기를 바꿀 수 있으며, 세로 화면과 가로 화면을 따로
     기억합니다.
   - Android 설정 화면(한국어 기본): 완료. 점 세 개 표시를 누르면 열립니다.
   - 두 화면을 한 장의 그림으로: 3D 장면은 완료([tall-view.ko.md](tall-view.ko.md)).
   - **게임이 자기 화면 위쪽에 그리는 범위 넓히기.** 게임은 아래 화면 밖의 것을 생략하므로, 이어진
     화면의 위쪽에는 통째로 화면 위에 있는 것들이 빠집니다. 게임의 물체(액터)는 완료: 게임이 물체를 그릴지
     묻는 곳에 훅을 걸었습니다([tall-view.ko.md](tall-view.ko.md)). 시뮬레이션은 건드리지 않으며 녹화는
     디컴프와 같은 프레임을 냅니다. 남은 일: 땅과 그 위에 서 있는 것들(나무, 건물)은 다른 코드가 그립니다.
     디컴프에서 그 코드를 찾아 화면 위쪽에서 생략하는 것이 있는지 보고, 같은 방식으로 넓혀 녹화로 검증합니다.
   - 실제 휴대폰의 카메라 구멍과 둥근 모서리: 기기에서 확인 필요.
   - 도루묵씨 켜기/끄기: 완료, 기본은 끔(설정의 `resetti=1`이나 `--resetti`로 다시 나오게 함). 게임은 마을을
     불러올 때 지난 플레이가 저장 없이 끝났는지 묻는데, 꺼 두면 그 답을 "아니오"로 만듭니다
     (`port/src/game_hooks.c`). 위치는 디컴프의 읽기 쉬운 소스에서 찾아 ROM 코드로 확인했습니다. 다만 불러올
     플레이된 마을의 세이브가 없어서 아직 끝까지 플레이해 확인하지는 못했습니다.
   - 자동저장. 세이브는 게임의 상태 블록(메모리 0x173fc바이트)을 체크섬과 함께 카드에 두 번 쓴 것입니다
     (`decomp/clean/main/activity_card.c`, `card_save.c`). 할 일: 게임이 쓰기 전에 정리하는 것들(주머니, 날짜
     표시, 플래그)을 파악하고, 게임이 스스로 저장할 수 있는 순간(야외, 대화·메뉴 없음)에 대화창 없이 같은
     쓰기를 1분 정도마다, 그리고 앱이 백그라운드로 갈 때 합니다. 쓴 것이 제대로 불러와지는지 확인하려면
     플레이된 마을의 세이브가 필요합니다.
3. **소리.** 완료: 디컴프의 `runtime/sound.c`를 그대로 쓰고, 그 출력 장치 부분에 Windows의 waveOut 대신 SDL
   오디오 큐를 붙였습니다(`port/src/sound_sdl.c`). 소리를 켜면 런타임이 게임의 시퀀서도 함께 돌리므로 프레임이
   디컴프의 소리 끈 녹화와 달라집니다(검증은 소리를 끄고 합니다). 남은 일: 음량 설정, DS보다 느리게 도는
   휴대폰에서 생기는 끊김 처리.
4. **Vulkan 렌더러**(계획은 [renderer.ko.md](renderer.ko.md)). DS의 3D 엔진을 GPU로 그려서 3D 장면이 휴대폰의 해상도로, 안티에일리어싱과
   함께 나오게 합니다. 2D 레이어는 그 위에 확대해 얹습니다. OpenGL ES는 대체 경로로 남깁니다. 이것은
   소프트웨어 렌더러의 출력을 바꾸는 것이므로 프레임 검증은 별도 모드가 필요합니다(소프트웨어 렌더러가
   기준으로 남음).
5. **함께 하기.**
   - 포트 유저끼리: 디컴프가 시뮬레이션하는 로컬 무선을 프로세스 간 파이프 대신 네트워크로 실어 나릅니다.
   - 게임 자체의 네트워크 코드로 닌텐도 Wi-Fi 커넥션 접속. 디컴프가 시뮬레이션하는 액세스 포인트를 실제
     네트워크로 열고 서버는 DNS로 고릅니다. 그러면 실기에서처럼 사설 서버가 동작하고, 포트 유저와 실기
     유저가 같은 서버에서 만납니다.
   - 포트 유저용 자체 서버.
   - 게임이 읽는 본체 설정(사용자 이름, 생일, Wi-Fi 커넥션 식별 정보)은 포트가 처음부터 직접 만듭니다.
     펌웨어나 NAND 이미지는 쓰지도 읽지도 않습니다.
   - 실기와의 DS 간 로컬 무선은 불가능합니다. 휴대폰은 DS의 무선 프로토콜을 주고받을 수 없습니다.
6. **속도(휴대폰에서 필요하면).** 먼저 프로파일링, 그다음 ARM 블록 번역기(`arm_x86.c`가 구조를 보여 줌)
   또는 ARM에서의 컴파일된 형태.
7. **업스트림 기여.** 디컴프 런타임이 다른 환경에서도 그대로 빌드되도록 작은 변경을 제안해 포트의
   대체 코드를 줄입니다.
